# Участие в Remains: Unity

Проектом единолично руководит Hemito. Только он принимает изменения в основную
ветку, определяет roadmap и выпускает официальные релизы. Участие не передаёт
управленческие полномочия или права на оригинальные ресурсы.

## Ошибки и предложения

Используйте шаблоны Issues. Для ошибки укажите commit/сборку, Unity/Windows,
шаги воспроизведения, ожидаемый и фактический результат, число игроков и host/client.
Отмечайте, использовался ли новый или сохранённый мир, localhost или LAN.
Удаляйте секреты, личные данные и ненужные личные пути из приложенных логов.
Не публикуйте обнаруженные ключи и пароли в Issues: сообщите владельцу приватно.

Для предложения опишите проблему, ожидаемое поведение и влияние на сеть,
сохранения и модификации. Предложение не означает включения в roadmap.

## Pull Requests

1. До крупной работы обсудите объём в Issue. Создайте форк и отдельную ветку.
2. Сохраняйте GUID, `.meta`, версии зависимостей и лицензионные уведомления.
3. Пользовательские тексты пишите по-русски, идентификаторы кода — по-английски.
4. Проверьте импорт и сборку Unity, затем затронутые игровые сценарии. Для сети
   укажите число процессов, роли участников и проверенные переходы/сохранения.
   Явно перечислите непроверенное; старый успешный прогон не заменяет новую проверку.
5. В PR опишите проблему, изменение, проверки и происхождение добавленных ресурсов.
   Не включайте кеши, готовые сборки, секреты или материалы без права распространения.
6. Дождитесь решения владельца. PR может быть принят, возвращён на доработку
   или закрыт. Автоматическое слияние не используется.

Для собственного вклада в покрытый код подтвердите право предоставить его по
PolyForm Noncommercial 1.0.0 и с дополнительными разрешениями проекта:
[LICENSING.md](LICENSING.md), [ADDITIONAL_PERMISSIONS.md](ADDITIONAL_PERMISSIONS.md).
Другие условия и сторонние материалы перечисляйте явно до принятия PR.
Это не передача исключительных прав: автор сохраняет их на свой вклад.
Разрешения за пределами предоставленных прав требуют участия правообладателя.

Моды и форки должны соблюдать права всех авторов и не представляться официальными
релизами. Часть команд повторного экспорта ресурсов требует отдельно полученных
исходных материалов; для сборки имеющейся игры они не нужны.

## Для владельца

Изучите Files changed, происхождение ресурсов и результаты проверок. Проверьте
изменения в отдельной ветке. Для доработки используйте Request changes, для принятия
— Merge pull request, для отклонения — Close pull request с кратким объяснением.
Выдача collaborator-доступа для предложений и PR не требуется. Перед запуском
чужих скриптов или workflow прочитайте их. Не используйте force push.
