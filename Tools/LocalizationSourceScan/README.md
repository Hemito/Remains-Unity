# Инвентаризация исходных строк

Инструмент читает C# через Roslyn из установленного .NET SDK; Unity и загрузка NuGet-пакетов не требуются. По умолчанию исходники игры не изменяет.

```powershell
dotnet restore Tools/LocalizationSourceScan --ignore-failed-sources -p:NuGetAudit=false
dotnet run --no-restore --project Tools/LocalizationSourceScan -- --self-test
dotnet run --no-restore --project Tools/LocalizationSourceScan -- .
```

Первый позиционный параметр — корень репозитория, второй — выходной JSON. По умолчанию создаётся `source-manifest.json` рядом с инструментом. Проверяются Presentation, Runtime и Gameplay. Manifest не содержит абсолютных путей и времени запуска, поэтому повторный запуск с теми же исходниками даёт те же байты.

`entries` — кандидаты для исходной русской String Table; `excluded` — диагностический список исключений с причинами. Исключаются атрибуты, const, шаблоны сравнения, исключения, диагностические вызовы, имена GameObject и уже локализованные вызовы. Runtime содержит в основном проверочные harness: из него в entries допускаются только PrototypeRuntime и ProjectStorage. Это синтаксическая инвентаризация: косвенно переданные сообщения разработчику могут остаться среди кандидатов; автоматической замены кода нет.

`key` — явный начальный идентификатор `source.<file>.<16 hex SHA256 Russian source>`. Одинаковые строки внутри файла объединяются с сохранением всех locations. После подключения ключ должен сохраняться при редактуре перевода: повторная генерация с изменённым русским текстом создаст новый кандидат, а не миграцию существующего ключа. До массового внедрения ключей нужна отдельная привязка к вызовам/постоянный реестр ключей.

`entries[].registered=true` означает, что строка уже находится внутри явного вызова GameLocalization.UiText/Format. Её ключ считывается из первого аргумента, поэтому сохраняется при изменении RU текста. Для первоначального подключения в таблицы импортируйте registered entries; остальные являются кандидатами для ручной проверки.

Режим `--rewrite` заменяет RU литералы/интерполяции в правой части присваивания `.text`, известных UI factory/notice вызовах и вручную проверенном списке форматирующих UI классов. Также включён KeyboardBindings; его definitions используют ленивые Func<string>, чтобы подписи не застывали на языке первого запуска. Режим сохраняет пользовательские переменные, исключает уже зарегистрированные вызовы и LocalizedUiText, проверяет отсутствие новых синтаксических ошибок. Вызовы с интерполяцией сохраняют исходный FormattableString; прочие получают UiText. Повторный запуск не создаёт вложенных обёрток. RU условные значения внутри интерполяций локализуются отдельно. Имена ui.Panel — только имена объектов и не локализуются. Перед расширением whitelist нужна проверка контекстов и последующая компиляция Unity.

Для интерполяции `russian` содержит составной формат .NET (`{0}`, `{1:0}` и т. п.). `placeholders` сохраняют индекс, выравнивание и формат; `locations[].expressions` сохраняют исходные C# выражения в том же порядке. Выражения не вычисляются и не преобразуются в строки. При внедрении использовать исходную интерполяцию как `FormattableString`, чтобы сохранить runtime-типы аргументов. Scanner не выполняет semantic compilation и не утверждает статические типы выражений.

Самопроверка проверяет шаблоны с форматом и двумя аргументами, исключение констант и логов. Ключи и шаблоны не являются Unity Smart String: импортёр должен явно выбрать совместимое форматирование, не включать Smart String вслепую.
