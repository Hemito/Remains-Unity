# Повторное использование исходной локализации

1. При закрытом пользовательском Unity Editor выполнить фоновую команду `-executeMethod Remains.Editor.LocalizationReuseExport.RunBatch`. Она экспортирует фактические русские UI-таблицы, описания предметов и отличающиеся от оригинала названия в `own-strings.json`. Экспорт не переписывает исходные переводы.
2. `dotnet run --project Tools/LocalizationReuse -- --self-test` проверяет нормализацию и защиту аргументов.
3. `dotnet run --project Tools/LocalizationReuse -- .` строит детерминированные отчёты `docs/history/localization-reuse-20261111.{md,json}` и применяемую карту `reuse-map.json`.

Исходник: девять каталогов `RemainsUnity/Assets/Remains/Editor/LocalizationSources/`. Добавленные нами `unity/…` не считаются локализацией оригинала. Каталоги содержат исходные ключи с ordinal повторов, поэтому неоднозначные русские подписи не склеиваются молча.

Точное совпадение и нормализация регистра/пунктуации применяются только к строкам без аргументов, когда все повторяющиеся исходные ключи имеют согласованные переводы. Нормализация не меняет наш русский текст. Дубликаты с разными переводами попадают в `ambiguous`. Шаблоны `{0}`/`@1`/`#1` требуют явного адаптера аргументов и автоматически не копируются.

`semantic-mappings.json` содержит отдельные проверенные смысловые соответствия и предложения на просмотр. Только `approved:true` включается в применяемую карту. `ownRussian` защищает от устаревшего решения после изменения собственного текста. Поиск по словам предлагает до трёх кандидатов; это не подтверждённый перевод и не автоматическая замена. Новые описания механики нельзя заменять похожими исходными обещаниями.

Карта `reuse-map.json`: `schema:1`, `mappings:[{table,key,russian,originalKey,originalRussian,matchType,reason}]`. Все записи сохраняют собственный стабильный ключ. Авторинг копирует лишь имеющиеся иноязычные значения найденного исходного ключа; русский исходник остаётся нашим. Отсутствующие языковые значения не выдумываются. Подробный JSON-отчёт содержит все переводы каждого кандидата.

Количество учитывается по `table/key`, а не по уникальному русскому тексту: одинаковые кнопки разных окон перечислены отдельно. Большая доля списка — описания предметов; разбивка UI/названий/описаний дана в отчёте. Повторный запуск не содержит времени, абсолютных путей или случайных ID. Инструмент использует C#/.NET 8 и не требует NuGet-пакетов.
