# Remains — браузерный редактор комнат и раскладок

Отдельный статический сайт на .NET 8 / Blazor WebAssembly. Unity и сервер приложений пользователю не нужны. Файлы обрабатываются в браузере, черновики остаются в IndexedDB. Сайт не отправляет комнаты в сеть.

**Текущее состояние:** рабочие редактирование комнат и раскладок, поиск статических маршрутов и локальная сборка сайта. Эталонный предпросмотр света заблокирован отсутствующим исходником `LightReference.cs`; весь этап 1 пока не принят. Сайт этой веткой автоматически не развёртывается.

## Собрать и открыть

Нужны Python 3 и .NET SDK 8.0.4xx; зависимости Blazor закреплены в `Web.csproj`. Убедитесь, что Git LFS подтянул PNG игры.

```sh
python3 Tools/RoomEditor/build.py
python3 -m http.server 8181 --bind 127.0.0.1 --directory Tools/RoomEditor/artifacts/wwwroot
```

Откройте `http://127.0.0.1:8181/`. Для SDK вне PATH: `build.py --dotnet /path/to/dotnet`. Каталог `artifacts/wwwroot` — готовый статический сайт: включает `_framework`, графику и уведомления о лицензировании. Никакого Unity-кода во время сборки не исполняется. Для размещения в подпапке используется относительный `<base href="./">`; входная страница остаётся `index.html`.

`prepare-assets.py` повторяемо копирует **уже публично выгруженные** определения, PNG и манифест из `Rooms/Original`, 57 комнат, реальные `movement.json`/`anatomy.json` и файлы лицензирования. Он не заменяет закрытый конвертер исходной графики. Графика загружается по мере показа превью и спрайтов.

## Комнаты

- Создать, открыть и скачать `.room.json`, открыть комнату оригинала как копию, изменить имя и размер. При уменьшении непустой области нужно явно разрешить обрезку. Координаты содержимого сохраняются относительно нижнего левого угла.
- Семь клеточных слоёв и два слоя размещений; отдельная видимость, поиск материалов и типов с превью.
- Кисть с непрерывной траекторией, прямоугольник, заливка, ластик, пипетка, выделение. Один штрих — один шаг отмены. Копирование/вставка переносят все слои, объекты и декор, назначают новые уникальные ID и перенаправляют внутренние связи. Зеркало работает на выбранном клеточном слое и использует `MirrorForm` направленных форм.
- Объекты/декор: поставить, выбрать в списке, переместить, удалить. Известные числовые параметры декора `w/h/a/fr/lon`, которые читает `RoomSpriteLayout`, имеют числовые поля. Остальные параметры редактируются JSON-объектом **строк**: в публичном каталоге нет полной схемы типов параметров. Неизвестные параметры не угадываются и не теряются.
- Связи объектов показываются линиями; можно добавить/удалить `targ`, остальные поля существующих связей сохраняются.
- Разъёмы — исходный массив значений по слотам. Проверки формата, неизвестных определений, ссылок и статической геометрии используют библиотеку игры.
- Отмена/повтор, горячие клавиши B/R/F/E/I/S и Ctrl+Z/Y/C/V. Черновик сохраняется после изменения; при открытии страницы восстанавливается. Скачивайте файл для надёжного хранения: очистка браузера удаляет черновики.

Холст рисует реальные PNG по маскам клеток: углы и отражения, непрерывную текстуру от начала комнаты, бордюры/пол, частичную высоту, задние/передние материалы, лестницы и ступени. Декор и объекты размещает существующий `RoomSpriteLayout`; окна стирают только фон/задние стены/декор с `EraseFirst`, открывая дальний фон. Смешивание normal/multiply/исходный 2x-overlay и максимальная альфа масок повторяют игровые шейдеры. Настройки `backwall/backform/fon/lon` берутся из комнаты и каталога земель; редактор позволяет править строковую карту настроек. Сетку/линейку и подписи объектов можно включать отдельно.

Формирование команд выполняется C#-кодом, а состояния соседей — общим `RoomTerrainShapes` на видимой области с рамкой в одну клетку. WebGL2 рисует текстуры и маски с линейным смешиванием, CPU fallback использует те же команды, линейную билинейную выборку и mip-уровни. На входе2 (1152×600) fallback занял около 0,55 с; средняя разница с WebGL2 — 0,24 из 255 на цветовой канал. Разница округления не превращается в другой формат или другие правила слоёв. Это отрисовка, **не расчёт света**. Флаги старых Flash-фильтров материалов (`cont/potek/plitka/...`) сохраняются, но текущая публичная игра сама их не применяет: `RoomTerrainView` помечает это как stageB4, а `WorldTerrain.shader` не читает `Filter`. Параметры bevel/glow/drips не выдумываются и вместо них не подставляются произвольные CSS-фильтры.

Защитный предел документа — 4 млн клеток; холст показывает окно до 100×100 клеток. Для большой комнаты задайте «Левый столбец»/«Верхняя строка»: файл хранится полностью, а Canvas не превышает браузерные пределы.

## Раскладки карт

Вкладка «Карты» редактирует существующий `remains-factory-layout` v1. Карта — полный сохранённый выбор комнат; генератор не запускается повторно. Сохраняются версия генератора и обычные поля формата.

Можно выбрать комнату для каждой клетки, отразить её, добавить свои шаблоны из файла/редактора комнат, назначить выход существующей точке `remains:obj:player`, открыть стыки вправо/вниз, скачать и открыть `.layout.json`. Общая геометрия строится **игровым** `FactoryGridBuilder`, включая общую стену на стыке. Есть отмена/повтор, черновик, проверка разъёмов с учётом зеркала, постоянных ID экземпляров и связности через открытые стыки. Ctrl+Z/Y работает с активной вкладкой.

ID повторяющегося шаблона различаются координатами экземпляра, как в игре. Карта должна состоять из комнат одинакового размера и клетки: это ограничение существующего сборщика; произвольный размер отдельной комнаты формат поддерживает. Перед открытием раскладки с пользовательскими шаблонами добавьте их файлы. Карта ссылается на шаблоны и не упаковывает их внутрь раскладки; скачивайте комнаты отдельно. Черновик браузера включает все используемые шаблоны и восстанавливает пользовательские комнаты вместе с раскладкой; скачиваемый файл карты остаётся обычным файлом раскладки без вложенных комнат.

**Игровая загрузка пользовательских карт и переход на них не добавлены.** Совместимость чтения и общей геометрии проверяется библиотекой формата; для игры потребуется отдельная точка перехода и загрузчик пользовательских ресурсов.

## Поиск маршрутов

Это вычисление на C# / CPU в браузере. Ядро напрямую компилирует исходные игровые `ActorTerrainMotion`, `ActorStepMotion`, `SlopeContactMotion`, `RoomSupport`, `RoomSurfaces`, `RoomSurfaceIndex`, `HorizontalMotion`, `VerticalMotion`, `MovementSettings` и `LadderMotion`; `PortableMovementAdapter.cs` предоставляет небольшие математические типы и статические DTO вместо Unity runtime. Источник игровых файлов и их ревизия определяются этой же веткой репозитория, копий алгоритмов нет.

Параметры и габариты пони читаются из **тех же публичных ресурсов игры**, не из новых констант редактора. Кнопкой «Старт пути» задаётся начало с привязкой к ближайшей свободной опоре; поиск работает и по общей геометрии карты.

- Зелёные точки: найденный статический маршрут для стоящего пони через ходьбу/бег, удерживаемый прыжок и ступени. Подъём по лестнице использует общий игровой `LadderMotion`; спуск с проверкой контактов нарисованных ног пока не анализируется.
- Жёлтые точки: маршрут не найден конечным поиском. Это **не доказательство невозможности**.
- Нет спуска по лестнице с контактом нарисованных ног, приседания, разрушения, динамических тел, платформ, боевых воздействий и полной логики `MovementController`/поз. Положительная проверка статических ядер не заменяет игровую приёмку движения.
- Бюджет до 20000 клеток / 12 с / 1600 исследованных состояний, кооперативная отмена и возврат управления браузеру. При правке расчёт отменяется, старый результат сбрасывается. Интерфейс показывает время, состояние усечения и фактический старт.

Нативный замер крупнейшей опубликованной комнаты (1200 клеток, `tsekh3`, 48×25) в облаке: **316 мс, 128 состояний**, без усечения. Это замер навигации, **не света**; время зависит от машины и CLR/WASM. Максимальный искусственный файл 2000×2000 с семью слоями (28 042 250 байт): открытие, подтверждённая запись IndexedDB, скачивание байт-в-байт и восстановление после reload прошли в Chromium за **6,8 с**.

## Проверки

```sh
dotnet run --project Tools/RoomEditor/Checks/Checks.csproj -- RemainsUnity/Assets/Remains/Rooms/Original
# После сборки и запуска статического сервера; нужны Playwright и Chromium:
python3 Tools/RoomEditor/Checks/browser-checks.py http://127.0.0.1:8181
# Пиксельные проверки масок/окон/режимов смешивания (также нужен Pillow):
python3 Tools/RoomEditor/Checks/browser-render-checks.py http://127.0.0.1:8181
# Дополнительно: полный лимит 4 млн клеток / 7 слоёв (~28 МБ):
python3 Tools/RoomEditor/Checks/browser-large-checks.py http://127.0.0.1:8181
```

Нативные проверки отрисовки охватывают все **57** комнат (302040 команд,171 маска стирания), сверяют состояния углов/отражения, частичную высоту и совпадение полной комнаты с видимой областью. Браузерные пиксельные фикстуры отдельно проверяют непрерывную фазу текстуры при панорамировании, отражение альфы, MAX-стирание без вертикального переворота, неповреждённый передний план и линейное смешивание в WebGL2 и CPU fallback.

Нативные проверки действительно читают все **57** файлов и требуют побайтно одинаковой записи исходным игровым сериализатором. Проверяются также атомарность отказов, редактирование, зеркальные формы, перенос палитр/ID/связей, история, resize, раскладки/общая геометрия, непроходимая стена, прыжок через разрыв и отмена поиска. Браузерный сценарий проверяет выпущенную WASM-сборку, штрих, историю, выделение/вставку/зеркало, скачивание оригинала байт-в-байт, восстановление черновика, отмену поиска и карту. Снимки попадают во временный каталог или `ROOM_EDITOR_CHECK_OUTPUT`; путь Chromium можно задать `CHROMIUM_PATH`.

## Оставшиеся условия приёмки

1. Передать `LightReference.cs` и его нужные зависимости из закрытого `Tools/RoomConvert`. Их нет в исходниках или переданном архиве. Эталонный radiosity-свет не заменён другим алгоритмом; кнопка явно недоступна. Замер света на крупнейшей комнате и сравнение с игрой остаются заблокированы.
2. При появлении полной схемы параметров добавить остальные типизированные поля объектов. Старые Flash-фильтры требуют реализации в самой игре и опубликованных параметров, а не подмены в редакторе.
3. Расширить навигацию на полный набор перемещений, подтвердить результаты в игре; конечный поиск не объявлять доказательством недостижимости.
4. Для игровых пользовательских карт — загрузчик комнат/карт и переход на ручную карту; UI редактора не подменяет эту задачу игры.
5. Выбрать и отдельно развернуть статический сайт после ревью. Эта ветка не публикует сайт автоматически.

## Необязательная проверка действительных Unity-шейдеров

`NativeChecks/NativeShaderProbe.cs` — небольшая самостоятельная проверка `WorldTerrain` и `WorldSprite`, без сцены игры и без сборки Player. Для её запуска временно скопируйте файл в `RemainsUnity/Assets/Editor`, задайте переменную `ROOM_EDITOR_NATIVE_REPORT` абсолютным путём JSON-отчёта и вызовите `Remains.Editor.RoomEditorNativeShaderProbe.Run` в batchmode с графикой. После проверки удалите временный файл и его `.meta`. Проверка выводит линейные цветовые образцы материала/смешивания; она не претендует на проверку света или всего игрового рендера.

Фактическая Native-проба прошла на Unity 6000.0.39f1 / OpenGLCore / llvmpipe / Linear: четыре кадра 32×32 прочитаны в RGBAFloat из R32G32B32A32_SFloat RenderTexture. Максимальное отклонение RGB от аналитического эталона — 0,000543, альфы — 0; допуск — 0,003. WebGL2 и CPU fallback дополнительно совпали с этими настоящими пикселями в пределах двух значений 8-битного sRGB-канала. Проверка не охватывает освещение, весь игровой рендер или аппаратную производительность.
